# 工作流程规范(通用版)

> **仓库短描述(可作 GitHub / Gitee 仓库 Description)**:工作流程规范 —— 用 AI 真正"干成事"的 10 步闭环 skill,跨 WorkBuddy / Claude Code / Codex / Cursor 通用。

用 AI 把每一项工作从"模糊想法"推进到"合格交付"的 10 步闭环工作流程规范。融合斯坦福 STORM 多视角研究法与项目管理执行环。

- **规划模式(步骤 1–4)**:需求不清晰 / 重大决策前 / 写方案前
- **执行模式(步骤 5–10)**:任务已明确,要落地交付
- **全闭环(1–10)**:从模糊想法到可交付成果

完整提示词见 `references/prompts.md`。

## 为什么是"通用"的

本 Skill 采用开放的 **Agent Skills 标准**:一个 `SKILL.md`(含 YAML frontmatter:`name` + `description`)+ 可选的 `references/`、`scripts/`、`assets/`。
该标准由 Anthropic 提出,**Claude Code、Codex、Cursor、WorkBuddy 均兼容同一格式**——同一个文件夹丢进任一工具的 skills 目录即可,无需改写。

## 跨工具安装

| 工具 | 安装位置 | 作用域 |
|---|---|---|
| **WorkBuddy** | `~/.workbuddy/skills/workflow-standard/` | 用户级通用 |
| **Claude Code** | `~/.claude/skills/workflow-standard/`(个人)<br>`.claude/skills/workflow-standard/`(项目) | 个人 / 项目 |
| **Codex** | `~/.codex/skills/workflow-standard/`(个人)<br>`.codex/skills/workflow-standard/`(项目) | 个人 / 项目 |
| **Cursor** | `~/.cursor/skills/workflow-standard/`(用户)<br>`.cursor/skills/workflow-standard/`(项目) | 用户 / 项目 |
| **ChatGPT / Gemini / 豆包 / 元宝 / DeepSeek** | 无原生 skill 目录 | 直接复制 `references/prompts.md` 全文,替换 `【主题】` 后粘贴对话框 |

> 注:agentic 工具(WorkBuddy / Claude Code / Cursor)会自动按 `description` 触发或支持 `/workflow-standard` 手动调用,并强制遵守 SKILL.md 里的"交互硬规则"(如逐项检查一次一项)。纯对话工具里这些规则只是提示词,需你手动驱动节奏。

## 使用说明(按步骤)

### 第 0 步 · 调用 Skill

- **WorkBuddy / Claude Code / Cursor**:新会话直接输入 `/workflow-standard`,或用自然语言说:
  - "用工作流程规范推进 **【任务】**"
  - "帮我理清 **【任务】**"(→ 规划模式)
  - "帮我落地交付 **【任务】**"(→ 执行模式)
- **纯对话工具(ChatGPT 等)**:把 `references/prompts.md` 全文复制,把 `【主题】` / `【你的角色】` 替换成你的内容后粘贴对话框,按步骤走。

### 第 1 步 · 选模式

> **开场前置 · 目标对齐与任务画像**:无论哪种模式,Skill 都会先复述对任务的理解(范围 / 焦点 / 起点假设 / 不含 / 预期产出形态)让你确认,再问 3 个必答(角色场景、时间预算、交付标准)+ 可选补充。这是防止"AI 理解偏了你还跟着答"的关键护栏,详见 `SKILL.md` 的「开场 · 任务画像与目标对齐」节。

| 你想做什么 | 你怎么跟 AI 说 | 跑哪几步 |
|---|---|---|
| 理清 / 调研 / 重大决策前 | "帮我理清 **【任务】**" | 规划模式 1–4 |
| 落地 / 交付 / 规范流程 | "帮我落地交付 **【任务】**" | 执行模式 5–10 |
| 从想法到交付一个领域 | "用全闭环推进 **【任务】**" | 全 1–10 |

### 第 2 步 · 规划模式实操示例(以"要不要做内部知识库"为例)

> 规划模式是 **AI 单方产出**,你看着吸收即可,无需逐题作答。

```
你:用规划模式帮我理清"团队要不要自建内部知识库"。
AI(第1步·五视角):
  · 实践者:知识库最大的坑是"建完没人写",维护成本远高于搭建成本……
  · 学者:知识管理研究显示,检索效率提升 30% 以上的团队都有专职维护者……
  · 怀疑者:所谓"知识沉淀"多是幸存者偏差,废弃的知识库比没有更碍事……
  · 成本控制者:看 SaaS 订阅费 vs 自建服务器 + 人力维护的三年总成本……
  · 历史学家:每个公司都有一波"知识库运动",多数在一年后回归聊天记录……
你:继续。
AI(第2步·矛盾图):五视角里"实践者vs学者"直接冲突;唯一共识是"维护比搭建难"……
AI(第3步·综合简报):60秒总结 + 5个关键发现(按可靠性排序)+ 一条行动建议:先用飞书文档跑 3 个月 MVP 再决定要不要自建。
AI(第4步·同行评审):给 5 个发现打可靠性分(1–10),标出最没把握的一条,建议补"团队规模"视角。
```

### 第 3 步 · 执行模式实操示例(以"上线一个新功能"为例)

> 执行模式的 **逐项检查(第8步)** 和 **复述确认(第9步)** 需要你真人逐项作答 / 复述,质检员会一次只查一项,等你说完再继续——这是它最反人性也最有效的地方。

```
你:用执行模式帮我落地交付"给 App 加一个深色模式"。
AI(第5步·方案择优):3 个方案(纯 CSS 变量 / 主题框架 / 系统级跟随)+ 各自取舍 + 推荐序
AI(第6步·阶梯):5 级(从"配好设计令牌"到"通过全量回归测试")
AI(第7步·核心20%):按你的时间预算伸缩的 10 次执行计划(或 30min 精简 / 1 周扩展)+ 最终交付物(深色模式完整功能)
AI(第8步·逐项检查):
  第1项(基础):设计令牌是否已抽取到统一变量?请回答。
你:已把所有颜色抽成 CSS 变量,在 :root 里定义了深色语义色。
AI:判定 通过(90%)。对:变量抽取正确。差距:还没覆盖图片/图标资源的深色适配。
    补救:给图片加 filter 降亮度,图标换成可换色 SVG。下一项——
  …(依次推进到第 10 项,每项判定+差距+补救)
AI(第9步·复述确认):用大白话讲交付标准 → 等你用自己的话复述 → 挑出含糊处只重讲那部分 → 再让你讲一遍
AI(第10步·一页清单):一张"深色模式交付清单"(标准/检查项/常见坑/上场清单)
```

### 第 4 步 · 硬规则速览(SKILL.md 强制)

1. **逐项检查**:一次只查一项,等回答后再继续;每项判定(通过/不通过)、说对在哪、指确切差距、给可执行补救。
2. **复述确认循环**:必须等你用自己的话复述后,才指出含糊/跳步处并让你只对薄弱部分重讲。
3. **方案择优**:只给 3–5 个方案,标明取舍与推荐序,不堆 20 个链接。
4. **一页清单**:控制在 5 分钟可扫完的篇幅,用短条目不用长段落。
5. **证据与核实(能力感知)**:涉及事实/数据/外部信息时,先判断环境能否实时联网取证——能则标来源链接,不能则每条标 `[需核实]` 由你核对;禁止编造来源/URL。

### 反触发护栏(不启动条件)

满足以下情形时,Skill **不会自动跑完整十步**,而是降格处理:

1. **单点速答 / 简单咨询**:只问"这个怎么做"且没说"规范流程 / 拆解 / 全闭环",直接回答或只跑对应单步。
2. **文档 / PPT / 产物生成**:要"做个 PPT / 写报告文档",交给对应技能(PPT 生成、文档工具),本 skill 产的是执行路径与交付清单。
3. **单步请求**:点名只要某一步("五视角分析下需求" / "帮我做交付检查" / "一张交付清单"),只跑那一步。

### 一致性保障 · 逐环交接

十步之间靠"前一步产物是后一步输入"串联,防止各步各说各话。核心铁律:**严禁跳序**、**严禁凭空生成上游未支撑的新事实/新方案**、**上游缺失先向你确认输入、不编造上下文**。每步的输入 / 产出 / 完成判定,见 `SKILL.md` 的「逐环交接 · 依赖与完成判定」表。

### 可选 · 导出 HTML 交付卡(步骤 10.5,需你触发)

跑完十步后,想存成一张精美、可重开的交付卡?跟 AI 说「导出 HTML / 生成交付卡」,它会读取 assets/template.html 把已产出内容填进去,生成一张单文件 HTML 卡:

- 含:任务画像 persona 卡(角色 / 预算 / 标准)+ 执行阶梯 + 一页交付清单(闪卡)+ 检查项
- 默认仍是 Markdown 输出,只有你明确要求才生成 HTML(全工具通用;纯对话工具里输出 HTML 代码块,存成 .html 双击打开)
- 视觉规范见 references/design.md(中性蓝 / 青 / 琥珀、圆角无阴影、零外部依赖),不沿用任何第三方品牌配色
- 互动(逐项检查 / 复述确认)在对话里发生,HTML 只是收尾成品

### 注意事项

- **"10 倍速"是营销话术**:骨架有真东西(STORM 多视角 + 测试效应 + 复述确认 + 里程碑),但别期待字面 10 倍。
- **事实 / 数据 / 决策务必人工核实**:STORM 已知有来源偏差、过度关联问题,AI 自评不可全信;涉及法律/财务/医疗更需你自己把关。
- **联网取证按环境能力自动降级**:本 skill 不绑定具体工具——有实时联网能力就真搜并标来源;纯对话工具无工具时,每条事实标 `[需核实]` 由你自行核对,绝不伪造来源。
- **编程 / 设计 / 实操类,光对话不够**:第 8、9 步测的是"你讲得清",真交付还得配真实环境(做中学)。
- **别跳过逐项检查和复述确认**:这两步最反人性,却是最能暴露"假交付"的环节,跳过等于回到"随机执行=假推进"。
