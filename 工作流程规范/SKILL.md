# 工作流程规范(通用 Skill)

> 跨工具:本 Skill 采用开放的 **Agent Skills 标准**(SKILL.md + references/),同一个文件夹可直接放入 WorkBuddy / Claude Code / Codex / Cursor 的 skills 目录;纯对话工具(ChatGPT、Gemini、豆包、元宝、DeepSeek 等)无需安装,直接复制 `references/prompts.md` 全文即可。

想到哪做到哪 = 返工 = 假效率。本 skill 强制补齐 **路径 · 检查 · 压缩 · 反馈闭环** 四要素,让每一项工作从"模糊想法"到"合格交付"都有法可依。

> 注:本方法 = 斯坦福 STORM 研究环(步骤 1–4)+ 项目管理执行环(步骤 5–10)。前者偏"把事想清楚",后者偏"把事做扎实"。

## 两种模式 + 全闭环

- **规划模式(步骤 1–4,源自 STORM)**:适合"需求不清晰 / 重大决策前 / 写方案前"。
- **执行模式(步骤 5–10,源自项目管理)**:适合"任务已明确,要落地交付"。
- **全闭环(步骤 1–10)**:从模糊想法到可交付成果。

## 路由(按用户意图选择)

- 说"帮我理清 / 调研 / 决策 / 写方案前" → 规划模式(1–4)
- 说"执行 / 落地 / 推进这个任务 / 规范流程" → 执行模式(5–10)
- 说"从想法到交付 / 全闭环 / 标准作业" → 全闭环(1–10)

## 反触发护栏(明确不启动 / 降格处理)

满足以下任一情形时,**不要自动启动完整十步**,按对应方式处理:

1. **单点速答 / 简单咨询**:用户只问"这个怎么做 / 推荐哪个"等可直接回答的问题、且未说"规范流程 / 拆解 / 全闭环" → 直接回答即可,或只跑对应单步(如只要流程梳理就只跑第 1–2 步)。本 skill 是"把工作做扎实"的流程,不是问答机器人。
2. **文档 / PPT / 产物生成**:用户要"写份文档 / 做个 PPT" → 不跑流程闭环,明确告知并建议交给对应技能(如文档工具、PPT 生成);本 skill 产出的是执行路径与交付清单,不是排版产物。
3. **单步请求**:用户点名只要某一步("五视角分析下需求" / "帮我做交付检查" / "出张一页检查清单") → 只跑那一步,不强制补全十步。

## 开场 · 任务画像与目标对齐(必做前置)

收到任务后**不要立刻跑十步**,先做两件事:

### 第 0 步 · 目标对齐(复述确认,零摩擦)
AI 先复述对任务的理解,用户确认/纠正后才继续。对齐五要素(E2 结构化澄清):
- **范围**:边界在哪(如"做一个网站"是静态页还是带后端?给谁用?)
- **焦点**:最想解决的核心问题
- **起点假设**:默认当前已有什么(已有代码 / 资源 / 团队 / 时间)
- **不含**:明确排除什么(哪些不做,防止范围蔓延)
- **预期产出形态**:方案文档 / 可运行代码 / 流程规范 / 交付报告 —— 此一项同时用于模式路由

用户回"对/确认"或纠正;纠正则 AI 重新复述一次再确认。本环节是确认而非提问,**不计入必答数**。

### 第 1 步 · 任务画像(必答 3 + 可选)
确认目标后,问必答 3 项(其余可跳过,过程中按需追问):

1. **角色 / 使用场景**(必答)— 你是决策者 / 执行者 / 交付方?决定方案口吻与检查粒度
2. **时间预算**(必答)— 30 分钟 / 半天 / 1 周 / 长期;直接决定第 7 步执行计划伸缩
3. **交付标准**(必答)— 内部先跑通 / 对外交付 / 上线发布 / 过验收;校准执行落点、检查严格度

可选补充(想更准可填):
- 当前进度(可选;不填则第 8 步首项检查动态判定)
- 协作方式 / 团队情况(单人 / 多人 / 跨部门;读 / 视频 / 面对面)
- 成功标准(能用 / 能交付 / 能复用 / 能标准化)
- 验收受众(自己 / 领导 / 客户 / 团队)
- 真实联网偏好(要真实溯源证据慢但准 / 快速即可;对接 web-access)

> 原则:开场必答不超过 3 个,避免摩擦导致放弃。检查步骤(8–10)的真实水平靠逐项互动得出,不在开场硬问。

## 硬规则(交互约束,必须执行)

1. **逐项检查**:一次只检查一个交付项,等用户确认后再继续,严禁一次性列完所有结论。每项检查做四件事:判定(通过/不通过)、说对在哪、指确切差距、给出可执行的补救动作。若开场未填当前进度,首项用中等粒度探测,据结果动态调整后续粒度。
2. **复述确认循环**:必须等用户用自己的话复述任务理解 / 交付标准后,才指出含糊、跳步处并让其只对薄弱部分重新说明;未对齐前不进入新步骤。
3. **方案择优**:给方案只挑 3–5 个,标明各自的取舍(成本 / 时间 / 质量),排出推荐序,不堆 20 个链接。
4. **一页清单**:交付清单 / 检查表控制在 5 分钟可扫完的篇幅,用短条目不用长段落。
5. **证据与核实(能力感知)**:涉及事实、数据、外部信息或法律/财务/医疗类决策时:
   - 先判断当前环境是否有实时联网取证能力(如 WorkBuddy 的 web-access、Claude Code 的 WebSearch/WebFetch 等)。有 → 用它检索并**标注来源链接**;无 → 进入降级。
   - 降级时:每条事实/数据后追加 `[需核实]` 标记,并在产出末尾统一附"待核实清单",提醒用户以权威源头核对(STORM 已知有来源偏差、过度关联问题,AI 自评不可全信)。
   - **禁止伪造**:宁可声明"未实时核实",也不得编造来源、URL 或"据搜索显示"——伪造来源比不核实更危险。
   - 纯对话模式(用户复制 prompts.md):若用户提供了链接/资料,优先采信用户提供的,而非模型记忆。
6. **理解对齐护栏**:进入方案择优(5)、逐项检查(8)、复述确认(9)前,若 AI 对任务/范围的理解可能漂移,须先复述确认再继续;用户纠正后须重新对齐。
7. **逐环交接**:每步须显式消费上游产物(见「逐环交接 · 依赖与完成判定」表);严禁跳序生成、严禁凭空引入上游未支撑的新事实/新方案/新结论;上游缺失时先向用户确认输入,不编造上下文。

## 推荐串联

- 规划:五视角 → 矛盾图 → 综合简报 → 同行评审
- 执行:任务拆解 → 执行阶梯 → 按【时间预算】伸缩的核心20%(30min 精简单核 / 半天标准 / 1 周扩展) → 逐项检查 → 复述确认 → 一页清单
- 公式:**路径 → 检查 → 压缩 → 重复**

## 逐环交接 · 依赖与完成判定

前一步的产物是后一步的输入。本表强制每步显式消费上游,避免各步"各说各话"(硬规则 7 已约束;此处为可执行明细)。

**交接铁律**
- **严禁跳序**:除非「反触发护栏」允许单步请求,否则按依赖顺序推进,不得跳过某步直接生成下游。
- **严禁凭空生成**:下游步骤不得引入上游产物未支撑的**新事实、新方案、新结论**;若需外部信息,按硬规则 5 取证并标注。
- **上游缺失时**:若用户只跑单步(如只要交付检查),先按该步输入要求向用户确认"你想基于什么",不要编造上下文。

**依赖与完成判定表**

| 步骤 | 输入(上游产物) | 产出(下游消费) | 完成判定(怎么算做完) |
|---|---|---|---|
| 第0步 目标对齐 | 用户原始需求 | 对齐确认件:范围 / 焦点 / 起点 / 不含 / 预期形态 | 用户回"确认"或纠正后复述一致 |
| 第1步 任务画像 | 对齐确认件 | 画像:角色 / 时间预算 / 交付标准(+可选进度·协作·成功标准·验收受众·联网偏好) | 必答 3 项收集;可选项可空 |
| 1 五视角 | 对齐件(范围 / 焦点) | 5 个视角各自的"独门细节" | 5 视角不重复、且覆盖对齐"焦点" |
| 2 矛盾图 | 五视角产出 | ≥2 组冲突主张 + 各自证据 + 最可信判断 | 列出真实张力,非单纯罗列观点 |
| 3 综合简报 | 五视角 + 矛盾图 | 60 秒总结 + 关键发现 + 行动建议 | 未引入上游无依据的新事实 |
| 4 同行评审 | 综合简报 | 可靠性评级 + 被忽略视角 + 来源提醒 | 给出评级且 ≥1 个补充视角 |
| 5 方案择优 | 画像(目标/时间/标准)+ 对齐(焦点);全闭环时含规划产出(1–4) | 3–5 方案 + 取舍说明 + 推荐序 | 恰好 3–5 个、有取舍、有推荐 |
| 6 执行阶梯 | 方案 + 画像(时间/标准)+ 对齐(起点) | ≥4 级,每级含里程碑 / 动作 / 自检 | 落点匹配交付标准 |
| 7 核心20% | 阶梯 + 画像(时间预算伸缩)+ 协作 | ≤10 关键动作;每次含练习/资源/自检 + 最终交付物 | 动作精炼、有动手、有自检 |
| 8 逐项检查 | 核心20%(关键动作)+ 画像(交付标准定严格度 / 可选进度定起点) | 逐项记录 + 判定 + 强弱项 + 整改计划 | 逐项等确认、每项四件事、有最终评定 |
| 9 复述确认 | 逐项检查(薄弱点)+ 核心20% | 用户复述 + 含糊处重述记录 | 用户真实复述、薄弱重述后通过 |
| 10 一页清单 | 全部上游(简报 / 方案 / 核心 / 薄弱点 / 角色场景) | 5 分钟可扫完的交付清单 | 含定义/核心/易错/上场清单,篇幅可控 |

> 跨模式提示:规划模式(1–4) 与执行模式(5–10) 各自内部连续;全闭环时第 5 步可直接消化第 1–4 步产出(如用简报结论筛选方案),无需重做。

## 可选 · 导出 HTML 交付卡(步骤 10.5,需用户触发)

把聊完即逝的十步产物装订成一张可重开、可分享、可打印的单文件 HTML 交付卡。互动(逐项检查 / 复述确认)仍在对话里发生,HTML 只做收尾成品,不替代过程。

- 触发条件:用户明确说「导出 HTML / 生成交付卡 / 做成可点击成果页」才走;默认仍是 Markdown 内联输出(全工具通用,含纯对话工具)。
- 范围(核心卡):顶部任务画像 persona 卡(角色 / 预算 / 标准)+ 执行阶梯 + 一页交付清单(闪卡)+ 检查项。不生成完整 12 段长页。
- 做法:读取 assets/template.html,将占位符 {{TITLE}} {{ROLE}} {{BUDGET}} {{GOAL}} {{LADDER}} {{FLASHCARDS}} {{QUESTION_BANK}} 替换为已产出的内容(下游步骤产物,受硬规则 7 约束);不得引入上游未支撑的新内容。
- 视觉规范:严格遵循 references/design.md——中性蓝 / 青 / 琥珀配色、圆角 12px、无阴影、系统字体。不使用任何外部图片 / 字体 / CDN,零外部依赖。
- 配色版权:采用本 skill 自有中性配色,不沿用任何第三方视觉品牌色,避免授权争议。
- 跨工具:agentic 工具直接预览;纯对话工具输出完整 HTML 代码块,用户存成 .html 双击打开。

> 注:若用户只要交付清单 / 检查项,可只渲染对应段。
